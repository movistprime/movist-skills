# Movist 문서 정리

사용자가 문서 정리나 문서 구조 이전을 명시적으로 요청할 때 수행한다. 기준은 작업 저장소 `README.md`의 `문서` 절(역할별 문서 종류, 적는 것, 적지 않는 것, 코드 인용 규칙, 공통 금지 항목), `Docs/Issues/README.md`의 상태·`처리` 규칙, `Docs/3.0/Migration-Plan.md`의 `계획 읽는 법`, `AGENTS.md`다. 이 스킬은 기준을 다시 정하지 않고 적용만 한다.

## 범위 확인

- 대상 문서와 끝내야 할 상태를 사용자 요청에서 정한다. 요청이 넓으면 owner 묶음(예: 재생 핵심 API, FFmpeg 계층 API, 네트워크·원격 API, 앱 계층 API, 기능 Spec·Design, 작업 추적)으로 나눠 묶음마다 배정 파일을 정하고, 묶음 하나가 리뷰할 수 있는 커밋 하나가 되게 한다. 계획은 먼저 사용자에게 보이고 승인 뒤 시작한다.
- `git worktree list --porcelain`의 다른 worktree마다 `git -C <worktree> status --short`와 `git -C <worktree> diff --stat`로 같은 문서의 미커밋 변경을 확인하고, 다른 branch의 커밋은 `git merge-tree --write-tree`로 충돌을 미리 확인한다. 겹치는 파일과 그 변경의 의도는 사용자에게 알리고, 다른 worktree의 작업 폴더·index·stash 목록은 건드리지 않는다.
- `Docs/History`, `__original`, `Docs/Reports`, `Docs/3.0/Prototypes`는 명시적 요청 없이 읽거나 고치지 않는다. 예외는 `Docs/History`에서 옮기거나 지운 문서를 가리키던 링크와 그 문장을 최소로 고치는 것뿐이다.

## 판정

문서를 읽으며 문장 단위로 다음 넷을 판정한다. 판정의 기준은 README 표의 그 문서 행이다.

- 정합성: 구현 상태·동작·객체 이름·수치를 단정하는 문장은 `Sources/`, `Tests/`, `Package.swift`, `Movist.xcodeproj/project.pbxproj`를 grep·read로 대조한다. 폐기된 구조를 현재형으로 적은 문장은 제거하거나 과거형으로 바꾼다. 소스로 확인하지 못한 주장은 바꾸지 않고 "미확인"으로 보고한다.
- 중복: 같은 규칙·수치·lifecycle이 두 문서 이상에 문장 단위로 반복되면 README 표의 owner 하나에 남기고 나머지는 한 줄 요약과 링크로 바꾼다. 요약 한 문장과 링크는 중복이 아니다.
- 경계: 문서 행의 "적지 않는 것"에 해당하는 내용은 owner 문서로 옮기거나 지운다. 계약은 API 문서로, 후보 목록·검토안은 Research로, 남은 작업·미검증 범위는 Migration Plan 완료 조건으로, 결함·한계는 Issues로, 검증 방법·fixture 준비는 Validation Guide로 보낸다. 문서 전체가 이름과 다른 역할이면(계약을 담은 Design, 후보 목록인 Design) 그 역할의 이름과 위치로 옮긴다.
- 디테일: 그 문서의 수준보다 깊은 내용(실행별 수치, 끝난 전환 설명, 선언 사본, 함수 본문, 반복 면책 문장, 시점 표현, 개인 작업 경로, 검증 기록)은 지우거나 한 문장으로 줄인다. 결정 근거로 쓰인 측정값은 결론 한 문장으로 남긴다.

## 수정 원칙

- 계약의 의미를 바꾸지 않는다. 표현 정리, 중복 제거, owner 참조 교체, 폐기 구조 제거, 낡은 상태 갱신만 한다. 새 기능·새 결정을 추가하지 않는다.
- 제품 결정은 하지 않는다. 후보 행의 채택·삭제, 우선순위 변경, 고치지 않기로 한 결정은 사용자에게 선택지로 보고한다.
- 지우기 전에 그 내용이 owner 문서에 실제로 있는지 확인한다. 없으면 먼저 옮긴다. 옮길 owner가 배정 밖이면 지우지 말고 "타 묶음 요청"으로 보고한다.
- 다른 문서를 가리킬 때는 백틱 파일명이 아니라 링크를 쓴다. 문서 소개문은 "X는 [owner](owner.md), 남은 산출물과 완료 조건은 [Migration Plan Pnn](Migration-Plan.md#영역-pnn-…)이 소유한다" 형식으로 맞춘다. 절을 지우거나 옮기면 그 anchor로 들어오던 링크를 새 owner로 돌린다.
- 고유 내용이 없어진 파일은 들어오는 링크를 먼저 바꾼 뒤 `git rm`한다. 문서를 옮기거나 이름을 바꾸면 들어오는 링크와 앵커를 함께 고친다.
- 사소한 불일치(낡은 문장, 끊긴 링크, 중복 heading, 형식 위반)는 묻지 않고 고친다. 사용자에게는 결정이 필요한 것과 코드 결함만 보고한다.
- Markdown 문단·목록 항목·표 행은 한 물리 줄, 한국어, 식별자와 코드 키워드는 번역하지 않는다. 구조를 바꾸는 경우가 아니면 파일 전체를 다시 쓰지 않고 바뀌는 범위만 편집한다. 여러 문서를 같은 규칙으로 고칠 때는 python 스크립트로 바꾸고 치환 수를 `assert`로 확인한다.

## API 문서 변환

- 문서 상단에 `- 상태:` 한 줄을 두고 값은 `구현됨`, `부분 구현`, `승인됨·미구현` 중 하나다. 부분 구현이면 같은 줄에 구현된 범위와 남은 범위를 한 문장으로 적고 Migration Plan 영역을 링크한다.
- `swift` 블록은 protocol 요구사항만 남긴다. 값 타입·enum·class·actor의 선언 사본은 `| 타입 | 멤버 | 의미 |`(한 절에 타입이 여럿) 또는 `| 멤버 | 의미 |`(타입 하나) 표로 바꾼다. 한 줄 시그니처는 표의 멤버 칸에 쓴다.
- 멤버의 의미는 그 문서의 기존 서술에서 먼저 찾고, 없으면 source를 읽어 쓴다. 선언만 있고 설명이 없던 멤버를 source로 보충할 때는 보고에 "source에서 가져온 멤버"로 나열한다. 선언 블록에 있던 주석이나 조건은 표의 의미 칸이나 바로 아래 문장으로 옮긴다.
- 검증 절, 테스트 이름, fixture 생성 명령, 실행별 수치는 지운다. 검증 방법과 fixture 준비가 다른 문서에 없으면 Validation Guide로 옮기고, 미검증 범위는 Migration Plan 완료 조건에 적는다.
- target과 문서가 1:1인지 `Package.swift`의 target 목록과 대조한다. C shim·binary target은 wrapper target 문서가 다루고 test support target은 문서가 없다. 문서가 없는 target은 새 문서를 `승인됨·미구현` 또는 실제 상태로 만들고, 한 target을 여러 문서가 나누는 예외는 README 문서 묶음 목록에 적는다.
- 변환이 끝난 문서마다 문장 손실 검사를 한다. 옛 파일과 새 파일을 `다.`·`음.` 기준으로 문장으로 나눠 새 파일에 없는 옛 문장을 모두 나열하고, 표로 옮겨진 문장과 삭제한 검증·시점 문장을 제외한 나머지가 비었는지 확인한다. 남은 문장은 보고에 적는다.

## 작업 추적 문서

- Migration Plan의 영역 절은 목표(owner 문서 링크), 남은 산출물, 완료 조건(실기기·외부 조건과 닫을 Issues ID), 다음 단계로 미룸의 네 항목만 둔다. 구현된 범위는 `완료된 범위` 표에 영역당 한 문장과 계약 owner로 적는다. 영역을 파일로 나누지 않는다. Design 문서와 역할이 겹친다.
- Issues 항목은 `Docs/Issues/README.md`의 상태 넷과 `처리` 값 중 하나를 갖는다. `처리`가 빈 항목이나 규칙에 없는 상태를 만나면 제안 값을 표로 묶어 사용자에게 한 번에 확인받고, 확정 전에는 값을 쓰지 않는다. 완료 조건에 Issues ID를 적으면 그 항목의 `처리`를 `완료 조건: <영역>`으로 맞춘다.

## 병렬 작업

문서가 많으면 묶음마다 subagent 하나에 배정 파일 목록, 이 스킬의 판정·수정 원칙과 API 문서 변환 규칙, 확정된 수정 항목(문서·절·무엇을 어떻게)을 주고 배정 파일만 편집하게 한다. subagent는 문장 손실 검사, 링크 검사, `git diff --check`를 직접 돌리고 지운 문장, 옮긴 검증 정보, source에서 가져온 멤버를 보고한다. 다른 묶음의 파일은 읽기만 하고 필요한 수정은 "타 묶음 요청"으로 돌려받아 합친다. 편집이 끝나면 source에서 가져온 멤버의 의미를 직접 source와 대조하고, 삭제·축약된 줄의 고유한 계약·결정·완료 조건이 어느 문서에도 남지 않은 경우를 찾는다. 문서가 더 많으면 이 두 검사를 읽기 전용 subagent 둘로 나눈다.

## 검증과 보고

- 링크·앵커: `Support/Tools/doc_links.py`는 CLI가 없으므로 `check_links(repo, documents, changed)`를 python으로 불러 `(count, errors)`의 오류 목록이 비었는지 확인한다. `repo`는 저장소 절대 경로의 `pathlib.Path`, `documents`는 `Docs/**/*.md`(편집하지 않는 History 제외)와 `README.md`의 상대 경로 집합, `changed`는 검사할 문서의 상대 경로 집합이며 전체를 검사하려면 `documents`와 같은 집합을 준다.
- 형식: 줄바꿈된 문단·깨진 표·같은 이름의 heading이 없는지, `git diff --check`, 금지 표현(실행별 수치, "이번", branch·통합 상태, 개인 경로)의 grep을 확인한다.
- 보고: 파일별 바꾼 내용, 소스로 확인한 사실, 바꾸지 않고 남긴 의심 항목과 이유, 사용자 결정이 필요한 항목, 타 묶음 요청, worktree 경로와 기준 커밋. 분량을 줄였다고 할 때는 줄 수가 아니라 절별 byte 증감을 적는다. 표와 링크는 줄 수를 줄이면서 byte를 늘릴 수 있다. 커밋은 요청이 있을 때만 [movist-commit](../movist-commit/SKILL.md)을 따른다.
