# Movist 문서 정리

사용자가 문서 정리나 문서 구조 이전을 명시적으로 요청할 때 수행한다. 기준은 작업 저장소 `README.md`의 `문서` 절(역할별 문서 종류, 적는 것, 적지 않는 것, 코드 인용 규칙, 공통 금지 항목)과 `Docs/Issues/README.md`, `AGENTS.md`다. 이 스킬은 기준을 다시 정하지 않고 적용만 한다.

## 범위 확인

- 대상 문서와 끝내야 할 상태를 사용자 요청에서 정한다. 요청이 넓으면 owner 묶음(예: 재생·FFKit API, Media Server·Center, App·UI, 기능 Spec·Design)으로 나눠 묶음마다 배정 파일을 정한다.
- `git worktree list`의 다른 worktree에 같은 문서의 미커밋 변경이 있으면 `git -C <worktree> stash create`로 스냅샷 커밋만 만들어 `git merge-tree --write-tree`로 충돌을 먼저 확인하고 겹치는 파일을 사용자에게 알린다. 다른 worktree의 작업 폴더·index·stash 목록은 건드리지 않는다.
- `Docs/History`, `__original`, `Docs/Reports`, `Docs/3.0/Prototypes`는 명시적 요청 없이 읽거나 고치지 않는다.

## 판정

문서를 읽으며 문장 단위로 다음 넷을 판정한다. 판정의 기준은 README 표의 그 문서 행이다.

- 정합성: 구현 상태·동작·객체 이름·수치를 단정하는 문장은 `Sources/`, `Tests/`, `Package.swift`, `Movist.xcodeproj/project.pbxproj`를 grep·read로 대조한다. 폐기된 구조를 현재형으로 적은 문장은 제거하거나 과거형으로 바꾼다. 소스로 확인하지 못한 주장은 바꾸지 않고 "미확인"으로 보고한다.
- 중복: 같은 규칙·수치·lifecycle이 두 문서 이상에 문장 단위로 반복되면 README 표의 owner 하나에 남기고 나머지는 한 줄 요약과 링크로 바꾼다. 요약 한 문장과 링크는 중복이 아니다.
- 경계: 문서 행의 "적지 않는 것"에 해당하는 내용은 owner 문서로 옮기거나 지운다. 계약은 API 문서로, 후보 목록·검토안은 Research로, 남은 작업·미검증 범위는 Migration Plan 완료 조건으로, 결함·한계는 Issues로 보낸다. 문서 전체가 이름과 다른 역할이면(계약을 담은 Design, 후보 목록인 Design) 그 역할의 이름과 위치로 옮긴다.
- 디테일: 그 문서의 수준보다 깊은 내용(실행별 수치, 끝난 전환 설명, 선언 사본, 함수 본문, 반복 면책 문장, 시점 표현, 개인 작업 경로)은 지우거나 한 문장으로 줄인다. 결정 근거로 쓰인 측정값은 결론 한 문장으로 남긴다.

## 수정 원칙

- 계약의 의미를 바꾸지 않는다. 표현 정리, 중복 제거, owner 참조 교체, 폐기 구조 제거, 낡은 상태 갱신만 한다. 새 기능·새 결정을 추가하지 않는다.
- 제품 결정은 하지 않는다. 후보 행의 채택·삭제, 우선순위 변경, 고치지 않기로 한 결정은 사용자에게 선택지로 보고한다.
- 지우기 전에 그 내용이 owner 문서에 실제로 있는지 확인한다. 없으면 먼저 옮긴다. 옮길 owner가 배정 밖이면 지우지 말고 "타 묶음 요청"으로 보고한다.
- 선언 사본을 지울 때 그 선언만이 설명하던 계약(필드 의미, 호출 순서, 오류 의미)은 source를 읽어 문장이나 표로 남긴다.
- 고유 내용이 없어진 파일은 들어오는 링크를 먼저 바꾼 뒤 `git rm`한다. 문서를 옮기거나 이름을 바꾸면 들어오는 링크와 앵커를 함께 고친다.
- 사소한 불일치(낡은 문장, 끊긴 링크, 형식 위반)는 묻지 않고 고친다. 사용자에게는 결정이 필요한 것과 코드 결함만 보고한다.
- Markdown 문단·목록 항목은 한 물리 줄, 한국어, 식별자와 코드 키워드는 번역하지 않는다. 구조를 바꾸는 경우가 아니면 파일 전체를 다시 쓰지 않고 바뀌는 범위만 편집한다.

## 병렬 작업

문서가 많으면 묶음마다 subagent 하나에 배정 파일 목록, 이 스킬의 판정·수정 원칙, 확정된 수정 항목(문서·절·무엇을 어떻게)을 주고 배정 파일만 편집하게 한다. 다른 묶음의 파일은 읽기만 하고 필요한 수정은 "타 묶음 요청"으로 돌려받아 합친다. 편집이 끝나면 읽기 전용 검증 subagent 둘을 돌린다. 하나는 `git diff`의 추가·변경 문장 중 사실 주장을 source와 대조하고, 다른 하나는 삭제·축약된 줄의 고유한 계약·결정·완료 조건이 어느 문서에도 남지 않은 경우를 찾는다.

## 검증과 보고

- 링크·앵커: `Support/Tools/doc_links.py`는 CLI가 없으므로 `check_links(repo, documents, changed)`를 python으로 불러 오류 목록이 비었는지 확인한다. `repo`는 저장소 절대 경로, `documents`는 `Docs/**/*.md`와 `README.md`의 상대 경로 집합, `changed`는 바뀐 문서의 상대 경로 집합이다.
- 형식: 줄바꿈된 문단·깨진 표가 없는지와 `git diff --check`를 확인한다.
- Issues: 정리 중 `처리`가 빈 항목이나 상태가 README 규칙에 없는 항목을 만나면 제안 값을 표로 묶어 사용자에게 한 번에 확인받고, 확정 전에는 값을 쓰지 않는다.
- 보고: 파일별 바꾼 내용, 소스로 확인한 사실, 바꾸지 않고 남긴 의심 항목과 이유, 사용자 결정이 필요한 항목, 타 묶음 요청, worktree 경로와 기준 커밋. 커밋은 요청이 있을 때만 [movist-commit](../movist-commit/SKILL.md)을 따른다.
